01. El Problema (Simulacro)

Imagina que este es el caso que viene en tu prueba:

📄 Enunciado

"Construya un bloque PL/SQL anónimo que analice la flota de la tabla VEHICULO_ELECTRICO. Para cada vehículo, calcule el total de días que fue arrendado durante el año 2024. Según ese total, determine el 'Estado de Mantenimiento': Si tiene más de 40 días, estado 'Urgente'. Si tiene entre 20 y 40 días, 'Programado'. Si tiene menos de 20 días o no tiene arriendos, 'Óptimo'. Inserte los resultados en la tabla REPORTE_MANTENIMIENTO. Vacíe la tabla al inicio para evitar duplicados."

03. Pausa Técnica: La Función EXTRACT

Para filtrar los arriendos que ocurrieron en el 2024, usaremos EXTRACT. ¿Qué es y para qué sirve?

¿Qué hace?

Extrae una parte específica de un campo de tipo Fecha (como un DATE o TIMESTAMP).

EXTRACT(parte FROM campo_fecha)
  • YEAR: Saca el año (Ej: 2024)
  • MONTH: Saca el mes (Ej: 12)
  • DAY: Saca el día (Ej: 31)

Ejemplos de Casos de Uso

-- Cumpleaños en Octubre
SELECT * FROM empleados 
WHERE EXTRACT(MONTH FROM fecha_nac) = 10;

-- Arriendos de HOY
SELECT * FROM arriendo 
WHERE EXTRACT(DAY FROM fecha_ini) = 
      EXTRACT(DAY FROM SYSDATE);

05. Pieza Lego 2: Matemáticas

El texto dice: "...calcule el total de días arrendado durante 2024"

-- Lego 2: Probando con un vehículo ficticio ('UW001') y nuestro amigo EXTRACT

SELECT SUM(dias_solicitados)
FROM ARRIENDO_VEHICULO 
WHERE cod_vehiculo = 'UW001' 
AND EXTRACT(YEAR FROM fecha_ini_arriendo) = 2024;
Espera un momento... Esta consulta tiene un problema mortal oculto si el vehículo no fue arrendado.

06. Pausa Técnica: El Peligro de NULL (NVL)

¿Qué pasa si intentamos sumar los días de un vehículo que nunca se ha arrendado?

El Problema Matemático

La base de datos no encontrará registros para sumar. Por lo tanto, el resultado de SUM() no es cero, es NULL (Vacío/Desconocido).

NULL + 10 = NULL

NULL / 2 = NULL

¡Cualquier operación matemática con NULL destruye todo tu cálculo y puede colapsar el INSERT!

La Solución: NVL()

NVL(valor_a_revisar, valor_de_reemplazo)

Es un escudo. Le dice a Oracle: "Si este cálculo da nulo, cámbialo por un cero para salvar la matemática".

-- Si SUM() da Nulo, escúpeme un 0
SELECT NVL(SUM(dias), 0) 
FROM arriendo;

07. Pieza Lego 3: Las Reglas

El texto dice: "Más de 40: Urgente. Entre 20 y 40: Programado. Menos de 20 o cero: Óptimo"

Lógica en Papel

Esto NO es SQL, son decisiones lógicas. Esto se maneja con memoria (Variables) e IF / ELSIF.

-- Lego 3: Estructura Mental
IF v_total_dias > 40 THEN
    v_estado := 'Urgente';
ELSIF v_total_dias >= 20 THEN
    v_estado := 'Programado';
ELSE
    v_estado := 'Óptimo';
END IF;

08. Pausa Técnica: DDL en PL/SQL

El requerimiento dice: "Vacíe la tabla al inicio para evitar duplicados".

¿Por qué vaciamos la tabla?

Para que nuestro bloque sea "Re-ejecutable". Si corremos el código 2 veces seguidas sin vaciar, el INSERT de la segunda vez chocará con los registros de la primera (Error de Clave Primaria).

¿Por qué usamos EXECUTE IMMEDIATE?

PL/SQL entiende nativamente comandos DML (INSERT, UPDATE, DELETE). Pero TRUNCATE es un comando DDL (Data Definition Language, altera la estructura).

Para obligar a PL/SQL a ejecutar comandos DDL, debemos empaquetarlos en SQL Dinámico:

EXECUTE IMMEDIATE 'TRUNCATE TABLE tabla';

09. Ensamblaje: El Esqueleto

¡Es hora de juntar los Legos! Empecemos por la zona DECLARE.

DECLARE
    -- 1. Ponemos nuestra "Pieza Lego 1" como Cursor
    CURSOR c_vehiculos IS 
        SELECT cod_vehiculo, modelo FROM VEHICULO_ELECTRICO;
        
    -- 2. Variables para recibir datos del Cursor
    v_cod    VEHICULO_ELECTRICO.cod_vehiculo%TYPE;
    v_modelo VEHICULO_ELECTRICO.modelo%TYPE;
    
    -- 3. Variables para nuestros cálculos futuros
    v_total_dias NUMBER(6);
    v_estado     VARCHAR2(20);
BEGIN
    -- 4. Vaciamos la tabla con SQL Dinámico (Requisito)
    EXECUTE IMMEDIATE 'TRUNCATE TABLE REPORTE_MANTENIMIENTO';
    
    -- Continuará...

10. Ensamblaje: El Motor (Loop)

Ahora le damos vida al bloque abriendo el cursor y creando el ciclo repetitivo.

    -- Venimos del DECLARE...
    
    OPEN c_vehiculos;
    LOOP
        -- Le pasamos el vehículo actual a la memoria RAM
        FETCH c_vehiculos INTO v_cod, v_modelo;
        EXIT WHEN c_vehiculos%NOTFOUND;
        
        -- Aquí dentro haremos matemáticas por cada vehículo
        -- ...
        
    END LOOP;
    CLOSE c_vehiculos;
    
    COMMIT;
END;

11. Ensamblaje: El Cerebro

Metemos las Piezas 2 y 3 adentro del Loop.

        -- Adentro del LOOP...
        
        -- Conectamos la Pieza Lego 2, protegida con NVL y EXTRACT
        -- Usamos v_cod en vez de 'UW001'
        SELECT NVL(SUM(dias_solicitados), 0)

        ELSIF v_total_dias >= 20 THEN
            v_estado := 'Programado';
        ELSE
            v_estado := 'Óptimo';
        END IF;

13. La Obra Maestra (Código Completo)

Así se ve tu bloque de código finalizado, ensamblado y listo para compilar.

DECLARE
    CURSOR c_vehiculos IS 
        SELECT cod_vehiculo, modelo FROM VEHICULO_ELECTRICO;
        
    v_cod    VEHICULO_ELECTRICO.cod_vehiculo%TYPE;
    v_modelo VEHICULO_ELECTRICO.modelo%TYPE;
    v_total_dias NUMBER(6);
    v_estado     VARCHAR2(20);
BEGIN
    EXECUTE IMMEDIATE 'TRUNCATE TABLE REPORTE_MANTENIMIENTO';
    
    OPEN c_vehiculos;
    LOOP
        FETCH c_vehiculos INTO v_cod, v_modelo;
        EXIT WHEN c_vehiculos%NOTFOUND;
        
        SELECT NVL(SUM(dias_solicitados), 0) INTO v_total_dias 
        FROM ARRIENDO_VEHICULO 
        WHERE cod_vehiculo = v_cod AND EXTRACT(YEAR FROM fecha_ini_arriendo) = 2024;
        
        IF v_total_dias > 40 THEN v_estado := 'Urgente';
        ELSIF v_total_dias >= 20 THEN v_estado := 'Programado';
        ELSE v_estado := 'Óptimo';
        END IF;
        
        INSERT INTO REPORTE_MANTENIMIENTO (cod_vehiculo, modelo, total_dias_2024, estado_mantenimiento)
        VALUES (v_cod, v_modelo, v_total_dias, v_estado);
    END LOOP;
    CLOSE c_vehiculos;
    
    COMMIT;
END;
