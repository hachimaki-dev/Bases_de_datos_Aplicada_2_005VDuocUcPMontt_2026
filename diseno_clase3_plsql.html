Idea central de esta clase: el puente entre SQL y PL/SQL
Hasta ahora los estudiantes asignaron valores con :=. Hoy aprenden que la BD también puede ser fuente de datos para sus variables — via SELECT INTO. Ese momento de "puedo leer la BD desde PL/SQL" es el giro narrativo de la clase.

SELECT INTO — el gran puente
Explicar por qué aparece: cuando haces un SELECT en PL/SQL, el resultado no va a la pantalla — va a una variable. Oracle necesita saber dónde guardar cada columna. SELECT col INTO var FROM tabla WHERE .... Reglas: 1 fila exacta. Excepciones: NO_DATA_FOUND y TOO_MANY_ROWS.

Cómo explicar SELECT INTO (el puente)
La pregunta que lo abre todo
Preguntar: "Ya declaramos variables. Ya les asignamos valores con :=. ¿Pero qué pasa si el valor que necesito está en la base de datos, no en mi cabeza?" Esperar respuestas. Luego: así es como Oracle lo resuelve.
Tres reglas que SÍ hay que memorizar
1
Exactamente una fila. Si el SELECT devuelve 0 filas → NO_DATA_FOUND. Si devuelve 2 o más → TOO_MANY_ROWS. El WHERE debe garantizar unicidad.
2
Columnas y variables deben coincidir en orden y tipo. Si el SELECT tiene 3 columnas, necesito 3 variables separadas por comas en el INTO.
3
No hay FROM dual con tablas reales. Mencionar que SELECT SYSDATE INTO v_fecha FROM dual sí funciona — DUAL es una tabla especial de Oracle para expresiones sin tabla real.
