Usuario vs. Tabla

Muchos principiantes confunden una "Tabla de Usuarios" con un "Usuario de Base de Datos".

Tabla de Usuarios

Es donde guardas el login y password de los clientes de tu app (ej. Netflix). Es solo data que tú analizas.

Usuario de BD

Es la cuenta a nivel sistema que Oracle usa para saber quién está ejecutando un comando SQL y si tiene permiso para hacerlo.

El Sistema de Privilegios

Un privilegio es un permiso para realizar una acción. En Oracle se dividen en dos categorías principales.

Privilegios de Sistema

Permiten hacer cosas a nivel motor de base de datos (crear sesión, crear tablas genéricas).

Privilegios de Objeto

Permiten interactuar con objetos concretos (hacer un SELECT o UPDATE a la tabla 'clientes').

-- 1. Creamos al usuario (Requiere privilegios de Administrador)
CREATE USER ana IDENTIFIED BY "Password_123";

-- 2. Privilegios de Sistema: Le damos permiso para conectarse (Vital)
GRANT CREATE SESSION TO ana;
GRANT CREATE TABLE TO ana;

-- 3. Privilegios de Objeto: Le damos permiso para ver la tabla clientes y agregar a ella
GRANT SELECT, INSERT ON clientes TO ana;

-- 4. Podemos quitarle un permiso en cualquier momento
REVOKE INSERT ON clientes FROM ana;

Empaquetando Permisos: Roles

Si tienes 50 empleados de ventas, ¿vas a escribir 50 líneas de GRANT SELECT ON...? No. Para eso existen los Roles. Un rol es simplemente una mochila en la que metes permisos y luego le pasas la mochila al usuario. 

-- 1. Crear el Rol
CREATE ROLE rol_ventas;

-- 2. Asignar privilegios al Rol (meter cosas en la mochila)
GRANT SELECT ON clientes TO rol_ventas;
GRANT SELECT ON pedidos TO rol_ventas;

-- 3. Asignar el Rol al usuario (entregar la mochila a Ana)
GRANT rol_ventas TO ana;

Prueba el Flujo Completo

Copia este bloque completo en tu editor SQL y observa cómo el sistema te bloquea al intentar acceder a lo que no tienes permiso.

-- Asegurate de tener permisos de administrador (como el usuario SYSTEM) para crear usuarios
-- y haber creado las tablas de la preparación.

-- 1. Creamos al usuario
CREATE USER beto IDENTIFIED BY "beto123";
GRANT CREATE SESSION TO beto;

-- 2. Le damos permiso SOLO para la tabla de pedidos
GRANT SELECT ON pedidos TO beto;

-- 3. Pruébalo (Dependiendo de tu IDE, deberías abrir una nueva conexión usando el usuario beto)
-- Si intentas esto conectado como beto:
-- SELECT * FROM pedidos; -- EXITO!
-- SELECT * FROM clientes; -- ERROR: La tabla o vista no existe (No tienes permisos)

Resumen de Seguridad 🔐

Privilegios Segmentados

No todo usuario debe ser administrador. Dividir entre privilegios de sistema y privilegios de objeto es la base de un diseño seguro (Principio del Mínimo Privilegio).

Roles Organizadores

Los Roles agrupan múltiples privilegios en un solo paquete. Si tienes 100 empleados en un área, creas 1 rol, no 100 grants individuales.
